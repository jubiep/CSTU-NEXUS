## 1. กลุ่มผู้ใช้งาน (User Personas)

| Persona | บทบาทและลักษณะ | ความต้องการหลัก |
|---|---|---|
| **CSTU Student**<br/>(นักศึกษาปัจจุบัน) | นักศึกษาสาขาวิชาวิทยาการคอมพิวเตอร์ ทุกชั้นปี (ปี 1–4) | ต้องการค้นหารายวิชา ศึกษารีวิวจากรุ่นพี่ ดูคะแนนความเข้ากันได้ และตั้งค่าความชอบในการเรียนเพื่อวางแผนลงทะเบียน |
| **CSTU Senior**<br/>(รุ่นพี่ผู้เคยเรียนรายวิชา) | นักศึกษาที่ผ่านการเรียนในรายวิชานั้นๆ มาแล้ว (ชั้นปีปัจจุบัน > ชั้นปีที่แนะนำของวิชา) | ต้องการส่งต่อประสบการณ์ เขียนรีวิว ให้คะแนนรายวิชาตามเกณฑ์ และเลือกปิดบังตัวตนได้ |
| **System Admin / System**<br/>(ระบบตรวจสอบและคำนวณ) | กลไกอัตโนมัติของระบบ | ตรวจสอบสิทธิ์การเข้าถึง คัดกรองนักศึกษา TU คำนวณชั้นปี และประมวลผลคะแนน Match Score |

## 2. Sprint 1: Core System & Reviewing (US-01 — US-05)

### US-01: การเข้าสู่ระบบด้วยบัญชีมหาวิทยาลัยธรรมศาสตร์ (TU Authentication)
- **Role:** As a **CSTU Student**
- **Action:** I want to **เข้าสู่ระบบด้วยเลขทะเบียนนักศึกษาและรหัสผ่าน TU**
- **Value:** So that **สามารถเข้าใช้งานระบบได้อย่างปลอดภัย โดยไม่ต้องสมัครบัญชีใหม่ และระบบสามารถระบุตัวตนและชั้นปีของฉันได้อย่างถูกต้อง**
- **Acceptance Criteria:**
  - **AC 1.1:** Given ผู้ใช้อยู่ที่หน้า Login เมื่อกรอกเลขทะเบียนนักศึกษา 10 หลักและรหัสผ่านถูกต้อง แล้วกด "เข้าสู่ระบบ" Then ระบบส่งคำขอไปตรวจสอบกับ TU AD Verify API และสร้าง Session ที่ปลอดภัย (HttpOnly Cookie)
  - **AC 1.2:** Given บัญชีที่ล็อกอินไม่ใช่ของนักศึกษาคณะวิทยาศาสตร์ สาขาวิทยาการคอมพิวเตอร์ (รหัสไม่ขึ้นต้นด้วยกลุ่มสาขา CSTU) When เข้าสู่ระบบ Then ระบบปฏิเสธการเข้าใช้งานและแสดงข้อความแจ้งเตือนข้อผิดพลาด
  - **AC 1.3:** Given ผู้ใช้กรอกรหัสผ่านผิด หรือบัญชีไม่ถูกต้อง When ส่งข้อมูล Then ระบบแสดงข้อความแจ้งเตือน และไม่อนุญาตให้เข้าใช้งาน
- **Priority:** High | **Sprint:** 1 | **Use Case ที่เกี่ยวข้อง:** U2

---

### US-02: การค้นหาและคัดกรองรายวิชา (Course Search & Filter)
- **Role:** As a **CSTU Student**
- **Action:** I want to **ค้นหารายวิชาด้วยรหัสวิชาหรือชื่อวิชา พร้อมคัดกรองตามชั้นปีที่แนะนำ**
- **Value:** So that **สามารถค้นหาวิชาที่ตนเองสนใจหรือวิชาที่ต้องลงทะเบียนตามแผนการศึกษาได้อย่างสะดวกรวดเร็ว**
- **Acceptance Criteria:**
  - **AC 2.1:** Given ผู้ใช้อยู่ที่หน้ารายการวิชา (`courses.html`) When พิมพ์คำค้นหา (รหัสวิชา เช่น `CS261` หรือชื่อวิชา) Then ระบบแสดงเฉพาะรายวิชาที่ตรงกับคำค้นหาทันที
  - **AC 2.2:** Given ผู้ใช้เลือกตัวกรองชั้นปี (ปี 1, 2, 3 หรือ 4) When กรองข้อมูล Then ระบบแสดงเฉพาะรายวิชาที่มี `recommended_year` ตรงกับที่เลือก
  - **AC 2.3:** Given ไม่พบรายวิชาที่ตรงกับเงื่อนไขค้นหา When แสดงผล Then ระบบแสดงข้อความแจ้งเตือนที่ชัดเจนว่าไม่พบข้อมูล
- **Priority:** High | **Sprint:** 1 | **Use Case ที่เกี่ยวข้อง:** U4

---

### US-03: การดูรายละเอียดรายวิชาและเซกชัน (Course & Section Exploration)
- **Role:** As a **CSTU Student**
- **Action:** I want to **เปิดดูรายละเอียดรายวิชา รายชื่อเซกชัน และอาจารย์ผู้สอน**
- **Value:** So that **ทราบข้อมูลเบื้องต้นเกี่ยวกับรายวิชาและตัวเลือกเซกชันที่เปิดสอนก่อนตัดสินใจลงทะเบียน**
- **Acceptance Criteria:**
  - **AC 3.1:** Given ผู้ใช้คลิกเลือกรายวิชาจากการค้นหา When หน้าแสดงรายละเอียดวิชา (`course-detail.html`) โหลด Then แสดงรหัสวิชา ชื่อวิชา ชั้นปีที่แนะนำ และรายชื่อเซกชันทั้งหมด
  - **AC 3.2:** Given รายวิชามีหลายเซกชัน When ดูรายชื่อเซกชัน Then แสดงเลขเซกชันและชื่ออาจารย์ผู้สอนของแต่ละเซกชันอย่างครบถ้วน
- **Priority:** High | **Sprint:** 1 | **Use Case ที่เกี่ยวข้อง:** U4

---

### US-04: การอ่านประวัติรีวิวของรายวิชาและเซกชัน (Read Reviews)
- **Role:** As a **CSTU Student**
- **Action:** I want to **อ่านข้อความรีวิวและคำแนะนำของวิชาและแยกตามเซกชันจากรุ่นพี่**
- **Value:** So that **เข้าใจบรรยากาศการเรียน รูปแบบการสอน และเตรียมตัวก่อนลงทะเบียนเรียนได้อย่างเหมาะสม**
- **Acceptance Criteria:**
  - **AC 4.1:** Given ผู้ใช้อยู่ที่หน้ารายละเอียดรายวิชา When ดูส่วนรีวิว Then แสดงรายการรีวิวทั้งหมดเรียงลำดับจากล่าสุดไปเก่าสุด พร้อมระบุชั้นปีของผู้เขียน ณ วันที่รีวิว
  - **AC 4.2:** Given ผู้ใช้เลือกเซกชันเฉพาะเจาะจง When กรองเซกชัน Then ระบบแสดงเฉพาะรีวิวที่เขียนถึงเซกชันนั้น
  - **AC 4.3:** Given วิชานั้นยังไม่มีรีวิวจากรุ่นพี่ When แสดงผล Then แสดงสถานะ No Reviews เพื่อแจ้งให้ผู้ใช้ทราบ
- **Priority:** High | **Sprint:** 1 | **Use Case ที่เกี่ยวข้อง:** U1

---

### US-05: การเขียนรีวิวรายวิชาพร้อมตรวจสอบสิทธิ์ (Write Review & Eligibility Check)
- **Role:** As a **CSTU Senior**
- **Action:** I want to **เขียนรีวิวรายวิชาและเซกชันที่ตนเองเคยเรียนมาแล้ว**
- **Value:** So that **ส่งต่อประสบการณ์และคำแนะนำที่มีประโยชน์ให้แก่รุ่นน้องในสาขา**
- **Acceptance Criteria:**
  - **AC 5.1:** Given นักศึกษาที่ล็อกอินมีชั้นปีปัจจุบันมากกว่าชั้นปีแนะนำของรายวิชา (`currentYear > recommendedYear`) และยังไม่เคยรีวิววิชานี้ When เข้าหน้ารายละเอียด Then ปุ่ม "เขียนรีวิว" สามารถกดได้ และเปิดฟอร์มเขียนรีวิวได้
  - **AC 5.2:** Given นักศึกษาที่ชั้นปียังไม่ถึงเกณฑ์ หรือเคยเขียนรีวิววิชานี้แล้ว When เข้าหน้ารายละเอียดหรือพยายามส่งรีวิว Then ปุ่มเขียนรีวิวจะถูกปิดการใช้งาน (Disabled) หรือระบบไม่อนุญาตให้ส่งรีวิว (HTTP 403)
  - **AC 5.3:** Given ผู้ใช้กรอกข้อความรีวิว เลือกเซกชันที่ต้องการ และกดส่ง When บันทึกสำเร็จ Then ระบบแสดงกล่องข้อความยืนยันความสำเร็จ และแสดงรีวิวใหม่ในหน้ารายการรีวิว
- **Priority:** High | **Sprint:** 1 | **Use Case ที่เกี่ยวข้อง:** U3, U5

## 3. Sprint 2: Preferences, Scoring & Privacy (US-06 — US-08)

### US-06: การให้คะแนนรายวิชาตามหัวข้อเกณฑ์มาตรฐาน (Structured Course Rating)
- **Role:** As a **CSTU Senior**
- **Action:** I want to **ให้คะแนนรายวิชาตามเกณฑ์ 5 ด้าน (แนวการสอน, สัดส่วนคะแนน, ความเร็ว, รูปแบบงาน, ปริมาณงาน/Workload)**
- **Value:** So that **ข้อมูลรีวิวมีมาตรฐาน เป็นเชิงปริมาณ สามารถนำไปประมวลผลวิเคราะห์และจับคู่กับความชอบของรุ่นน้องได้อย่างแม่นยำ**
- **Acceptance Criteria:**
  - **AC 6.1:** Given ผู้ใช้อยู่ในหน้าเขียนรีวิว When เลือกคะแนนเกณฑ์มาตรฐาน 5 ด้าน (0, 50, 100) Then ระบบบันทึกคะแนนแต่ละด้านพร้อมกับข้อความรีวิว
  - **AC 6.2:** Given ผู้ใช้ไม่ได้เลือกเกณฑ์บางหัวข้อ When บันทึก Then ระบบยอมรับค่าว่าง (null) สำหรับหัวข้อที่ไม่ได้ระบุได้ แต่ต้องมีข้อความรีวิว
- **Priority:** Medium | **Sprint:** 2 | **Use Case ที่เกี่ยวข้อง:** U6

---

### US-07: การเขียนรีวิวแบบปกปิดตัวตน (Anonymous Review)
- **Role:** As a **CSTU Senior**
- **Action:** I want to **เลือกเขียนรีวิวแบบไม่เปิดเผยตัวตน (Anonymous Mode)**
- **Value:** So that **สามารถแสดงความคิดเห็นและรีวิวประสบการณ์ได้อย่างตรงไปตรงมาโดยไม่ต้องกังวลเรื่องความเป็นส่วนตัว**
- **Acceptance Criteria:**
  - **AC 7.1:** Given ผู้ใช้เปิดตัวเลือก "ไม่เปิดเผยตัวตน" ในหน้าเขียนรีวิว When ส่งรีวิว Then ระบบจัดเก็บสถานะ `is_anonymous = true`
  - **AC 7.2:** Given รีวิวที่มีสถานะเป็น Anonymous When ผู้ใช้อื่นเปิดอ่านรีวิว Then แสดงชื่อผู้เขียนเป็นรหัสรุ่นพรางตัว (เช่น `68********`) และไม่ส่ง `studentId` หรือ `userId` ผ่าน API
  - **AC 7.3:** Given เจ้าของรีวิวเข้าสู่ระบบ When ดูรีวิวที่ตนเองเคยเขียน Then ยังคงสามารถแก้ไขข้อความรีวิวของตนเองได้
- **Priority:** Medium | **Sprint:** 2 | **Use Case ที่เกี่ยวข้อง:** U5, U6

---

### US-08: การตั้งค่าความชอบในการเรียนและการคำนวณ Match Score (Learning Preferences & Match Score)
- **Role:** As a **CSTU Student**
- **Action:** I want to **กำหนดความชอบในการเรียนของตนเอง 5 ด้าน และดูเปอร์เซ็นต์ความเข้ากันได้ (Match Score %) กับแต่ละเซกชัน**
- **Value:** So that **สามารถเลือกเรียนเซกชันที่สอดคล้องกับสไตล์การเรียนรู้และระดับ Workload ที่ตนเองรับไหวได้อย่างเหมาะสมที่สุด**
- **Acceptance Criteria:**
  - **AC 8.1:** Given ผู้ใช้อยู่ที่หน้า Preferences (`preference.html`) When ปรับระดับความชอบ 5 ด้าน (รูปแบบการสอน, สัดส่วนคะแนน, ความเร็ว, รูปแบบงาน, ระดับ Workload ที่รับได้) และกดบันทึก Then ระบบบันทึกลงในฐานข้อมูล และแสดงสถานะบันทึกสำเร็จ
  - **AC 8.2:** Given ผู้ใช้บันทึก Preferences แล้ว เมื่อเปิดดูหน้ารายละเอียดรายวิชา Then ระบบแสดงแถบ Match Score (%) ของแต่ละเซกชัน คำนวณจากความคล้ายคลึงระหว่าง Preference ของนักศึกษากับสถิติคะแนนรีวิวของเซกชันนั้น
  - **AC 8.3:** Given เซกชันนั้นยังไม่มีข้อมูลรีวิวเพียงพอ หรือผู้ใช้ยังไม่ได้ระบุ Preferences When แสดงผล Then ระบบแสดงสถานะ "ไม่มีข้อมูลเพียงพอ (No Data)" แทนการสร้างคะแนนจำลองขึ้นมาเอง
- **Priority:** High | **Sprint:** 2 | **Use Case ที่เกี่ยวข้อง:** U7
